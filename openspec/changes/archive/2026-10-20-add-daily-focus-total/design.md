## Context

- 引擎在階段結束時由 `tick` 產生 `phaseEnded` 事件（目前只有 `phase` 與 `endedAt`）；`useTimer` 以事件觸發提醒。
- 設定與計時進行中被鎖定，因此一段專注的時長在整段期間固定。
- 「10-sec test」會把工作時長改成 10 秒（`isTestRun`），不應影響真實統計。
- 全域規範：外部輸入需 runtime 驗證、不吞例外；專案為純前端，儲存在 localStorage。

## Goals / Non-Goals

**Goals:**
- 每完成一段專注，今日總計精確累加其時長，且每段只累加一次。
- 跨日自動歸零，重新整理後保留。
- 儲存資料損毀時不影響計時主流程。

**Non-Goals:**
- 歷史紀錄、圖表、休息統計、依實際經過時間（含中途 Restart）累計、跨裝置同步。

## Decisions

1. **只在「完整完成的專注」時累加，由事件驅動**
   - 引擎 `phaseEnded` 事件新增 `durationMs`：WORKING 為該段專注時長（`durations.workMs`），BREAK 為休息時長。`useTimer` 收到 `phase = WORKING` 的事件時呼叫統計模組累加。
   - 因為事件只在到期轉換時產生一次，不會重複累計（沿用 NFR-002 的保證）；Restart 會取消排程，中途專注自然不計入。
   - 替代方案：依實際經過時間累計（暫停、Restart 也算）→ 需追蹤每段起訖與暫停，邊界情況多（睡眠、跨午夜），使用者已選擇不採用。

2. **10 秒測試不計入**
   - `useTimer` 在累加前檢查 `isTestRun`；測試模式下的 WORKING 事件直接略過。

3. **儲存單日紀錄，以本機日期為鍵**
   - `localStorage` key `pomodoro:daily-focus`，內容 `{ version: 1, date: 'YYYY-MM-DD', totalMs: number }`。日期以本機時區的年月日組成。
   - 讀取時若 `date` 不是今天，視為 0；下一次累加時以今天日期覆寫。只保留今天一筆，不保留歷史（Non-Goal）。
   - 跨午夜的專注：歸屬到「結束當下」的日期。
   - 替代方案：以 `days` 對照表保存多日 → 為了未來可能的歷史功能而存的資料，屬於推測性設計，暫不採用。

4. **累加前重新讀取儲存值（read-modify-write）**
   - 多個分頁同時開啟時，每次累加都先讀最新值再寫回，避免用過期的記憶體值覆寫另一分頁的結果；不另外監聽 `storage` 事件，顯示在下一次重新整理或下一次累加時更新。
   - 已知限制：兩個分頁同一瞬間完成專注仍可能少算一次，P2 之前不處理。

5. **讀寫驗證與錯誤處理**
   - 讀取結果視為 `unknown`，以 type guard 驗證 `version`、日期格式、`totalMs` 為非負有限數；失敗時記錄警告並視為 0。
   - 寫入失敗時記錄錯誤並在畫面顯示明確訊息（沿用既有的 `errorMessage`），記憶體中的總計仍更新，僅本次有效。

6. **顯示**
   - 純函式 `formatFocusTotal(ms)`：無條件捨去到分鐘，0 → `0 min`、85 分鐘 → `1 h 25 min`、60 分鐘 → `1 h`。
   - 位置：主畫面計時圓盤下方、Restart 列之上，一行 `Today 1 h 25 min`；不使用 tooltip，文字為英文。
   - 顯示值隨「現在」重新計算日期鍵，因此跨午夜後無需重新整理即歸零。

## Risks / Trade-offs

- [使用者在專注快結束時 Restart 會損失全部時數] → 已確認的取捨；若日後需要，改採「實際經過時間」規則。
- [使用者更改系統時間或時區] → 日期鍵依本機時間，可能讓總計歸零或延續；列為已知限制。
- [localStorage 被清除] → 總計歸零，無備份。
- [多分頁並發] → 見決策 4。

## Open Questions

- 無；累計規則已由使用者確認（只計完整完成的專注）。
